## 1. 费用原则：需要实际付费就停止

Databento 历史数据通常按数据量计费，并非持有 API key 就可以免费下载。官方说明新团队有 125 美元免费 credits，团队共享、有效期 6 个月；不能假定这把比赛密钥仍有额度。实时数据涉及订阅，此次不用。[官方计费说明](https://databento.com/docs/faqs/usage-pricing-and-data-credits)

执行顺序：

1. 先确认比赛是否包了指定 dataset、历史日期及用量；有比赛免费授权时优先使用。
2. 如依赖免费 credits，由账号负责人确认余额、有效期、团队其他人的并发使用，以及是否有额外许可费用。无法确认零实际支出时，不下载。
3. 对准确的 dataset、symbols、schema 和日期区间先用 `metadata.get_cost` 估价，保存脱敏结果。估价不等于账户余额检查，也不是扣款上限。
4. 正价格请求只有在明确由免费额度/比赛授权覆盖，且有可靠防超额措施时才执行；否则跳过。估价失败或权限不明也停止，不能自动换成付费数据集。
5. 不开通订阅、不绑定支付方式、不自动充值。重复实验读取本地缓存，避免重复下载。

官方说明 `get_cost` 返回估计美元费用，最终按实际传输计费，因此“估价很低”不等于“保证不会花钱”。[费用估算接口](https://databento.com/docs/api-historical/metadata/metadata-get-cost?lang=python)

若没有可确认的免费真实数据：寻找官方明确免费的样本，或使用可合法本地使用的已有数据；仍没有时，用清楚标注的合成行情验证接口和记账，并在报告中写明 Databento 实际数据试跑未完成。不能把合成数据结果称为市场回测。

## 2. 控制数据范围

| 阶段 | 请求范围 | 用途 |
|---|---|---|
| A：接入检查 | AAPL、MSFT、SPY；2026-09-14 至 2026-09-19（结束日期不包含）；优先日线 | 检查认证、symbol、价格单位、缺失和时区 |
| B：最小回测 | 相同三个标的；2026-07-01 至 2026-10-01；日线 | 验证信号延迟、成交、持仓、成本、净值 |
| C：可选执行检查 | 同三个标的、一个完整交易日；分钟线 | 检查常规时段及开盘后执行假设 |

先通过 metadata 检查历史范围和 schemas；日期不覆盖时选择已有的连续完整时段并记录，不购买额外历史。每一步都重新检查费用，A 免费不代表 B、C 免费。

`EQUS.MINI` 是候选而非已确认选择。它提供日线和分钟 OHLCV，但聚合的是其组成场所的数据，不能直接当作全市场成交量。实际 dataset 由免费授权和覆盖决定。[数据集说明](https://databento.com/docs/datasets/equs-mini)

只下载明确列出的股票，禁止 `ALL_SYMBOLS`；暂不用逐笔成交、订单簿、期权或期货。少量现存股票仅用于工程验证，不能证明完整选股策略有效。

## 3. 团队统一数据接口的候选方案

Python 使用 `databento` SDK，环境固定版本；key 只从 `DATABENTO_API_KEY` 环境变量读取。原始行情和真实密钥不提交 GitHub，数据共享范围按供应商授权执行。

规范化行情表建议包含：

| 字段 | 约定 |
|---|---|
| `symbol`, `instrument_id` | 同时保留展示代码与供应商标识；记录映射 |
| `bar_start_utc`, `bar_end_utc` | UTC、有时区；不得将开始时间当作整根柱已可用时间 |
| `session_date` | 按 `America/New_York` 交易日历映射 |
| `open`, `high`, `low`, `close`, `volume` | 未复权可交易价格及成交量，明确单位 |
| `available_at` | 已确认的可用时间；没有发布时点时明确标注保守假设 |
| `dataset`, `schema`, `adjustment` | 数据来源、频率、复权状态 |

验收：检查重复行、OHLC 大小关系、负成交量、价格单位、缺失交易日和非交易时段。无成交产生的缺柱与下载失败要区分，不能全部填成零价。日柱聚合时段需要核对，不能直接宣称供应商日线开盘就是 09:30 正式开盘。[OHLCV 约定](https://databento.com/docs/schemas/ohlcv)

发生拆股、分红时检查处理口径；数据不足则标注局限，不把未处理公司行动的收益用于策略结论。Qlib 导入前单独检查复权因子和成交股数转换，不能用复权价直接下单。

## 4. 最小回测实验

先做两个容易手工核算的实验，不训练 LightGBM：

- **实验一：等权买入持有。**AAPL、MSFT 各占初始资产 50%，留足费用现金，以整数股成交；SPY 作为独立基准。核对现金＋股票市值＝净值。
- **实验二：简单轮动。**预留 20 个交易日计算动量，每周首个交易日，根据前一个交易日结束后可用的数据，在 AAPL、MSFT 中选择过去 20 日收益较高者，目标股票仓位 80%，其余现金。

这两个实验仅验证框架。两只股票和短样本不能用来证明选股能力；集中持仓也不是准备提交比赛的最终风控方案。

执行口径：

1. t 日数据完成后产生目标权重，最早 t+1 成交；不允许用当天收盘信号按当天收盘价买入。
2. 使用下一根已验证口径的日柱开盘价作为粗略成交代理；未核实时标注“供应商日柱开盘”，不等同于实际开盘后 5–20 分钟下单。
3. 先跑零成本对账版本，再跑单边总成本 10 bps 的工程测试，并用 5/20 bps 做敏感性检查；这些数值是测试假设，不代表 IBKR 真实收费。
4. 交易成本按买入和卖出绝对金额分别计算；先卖后买，禁止负现金与超卖。现金利息在第一轮设为零并披露。
5. 停牌或缺报价时不假定成交，记录原因；采用有限的价格延续估值时标记 stale，不能把旧价当新成交价。

输出 `orders.csv`、`positions.csv`、`daily_nav.csv`、净值图及摘要：收益、最大回撤、换手、成本、数据缺失、实际持仓率。短期夏普只作描述，不能据此选最优参数；本地指标不是官方赛事评分。
