## 风险矩阵接入与时间边界

读取 `outputs/risk_models_20261109/` 的52期紧凑协方差与对应Beta。三份元数据文件的SHA256固定在新配置中；NPZ逐次按版本哈希校验，即使有内存缓存，也不接受磁盘文件被修改。

- 矩阵为 `C = F × F.T + diag(d)`，`d`非负，检查维度、证券唯一性、有限值、计量单位，禁止pickle。
- 协方差数组只读，缺失证券不按零风险处理。
- 严格模式使用真实 `available_at`；本轮是显式 `exploratory_model_time` 模式，以历史模型截止进行假设回放。
- 所有52期矩阵在对应历史截止下的严格可见数仍为0，没有提升PIT验收状态。
- 实际回放行情与风险估计所用输入指纹必须一致，估计窗口终点不能晚于信号日。

本次研究使用最新冻结复权历史、假设发布时间及既有公司行动保护，沿用之前所有研究偏差。不是实际在历史当天运行过的策略，也没有启用完整指数增强。

## 风险诊断

每次有效目标同时记录：原等权目标、优化后目标、当日实际持仓。

```text
年化方差 = 252 × w.T × C × w
年化波动 = sqrt(年化方差)
净资产口径Beta = sum(w_i × beta_i)，现金Beta为0
单股年化方差贡献 = 252 × w_i × (Cw)_i
```

风险贡献是方差贡献，允许因相关性出现负值，全部贡献之和须等于组合年化方差。Beta覆盖缺失时返回不可计算，不补零。跟踪误差保持不可计算，因为仍没有历史基准成分权重；组合波动不是跟踪误差。

本轮目标组合平均预测年化波动约10.58%。这是各信号日的模型诊断均值，不是实现波动、收益或风险合规证书。

目标组合净资产口径Beta估计均值约0.331，范围约-0.090至0.763，52期都低于原完整方案的0.85下限。本版没有强制该下限，不能称为满足完整方案的Beta约束；它目前提供的是明确暴露这一差距的诊断。

## 权重优化接口

`optimize_weights(covariance, sectors, ...)` 处理预先选定的股票，不替代TopK选股，也不使用整数／二元变量求解持股数量。输入候选数超过指定持股上限会拒绝。

固定目标函数：

```text
minimize 252 × w.T × C × w + 0.01 × ||w - reference||²
subject to
    sum(w) = target_equity_weight
    0 <= w_i <= 0.04
    每个行业 sum(w_i) <= 0.20
```

`reference` 为原策略目标权重，0.01为预先固定的锚定惩罚。本版没有用选股排名冒充预期收益。Beta与主动风险仅作诊断或保持缺失，不把未实现的限制写成已满足。

求解采用投影梯度下降。投影通过二分求总仓位乘子，结合逐行业的截断单纯形投影，同时处理非负、单股、行业及总仓位约束。按风险矩阵最大特征值和锚定项确定步长，检查PSD、迭代收敛、目标函数不恶化和约束残差。

求解不收敛、暴露容量不足或数值检查失败时明确报错；账户适配层不发送新目标并留存原因。数据文件损坏触发完整性错误，停止运行，不能静默换用其他矩阵。

## 为什么当前配置无法产生不同权重

```text
20 × 4% = 80%
```

20只股票若有任意一只低于4%，其他股票都不能超过4%，因此无法仍然合计80%。选不满时沿用原规则：每只4%、其余现金；优化器对这个较低目标暴露同样给出唯一容量解。

程序识别这类问题后返回 `unique_capacity_solution`，直接保留精确Decimal的4%目标，避免浮点转账导致微小、无意义的交易。

通用接口已在有自由度的案例中验证，例如两资产方差分别1和4、无相关、80%仓位且上限不绑定时，解析最小方差权重为64%／16%，数值结果一致。该合成测试放宽了参数，只验证接口，没有更改当前20只研究策略。

后续若要实际调整权重，需要明确新版本：例如持股数允许大于20，或调整单股上限；这些都会改变策略，须另行冻结和对照，不能在本轮偷偷启用。

风险矩阵之前的日期保持现金，不计入以下评估；此后若目标或实际持仓不在风险股票池内，两组都跳过该次目标，保留实际持仓，并记录原因。不会为了凑矩阵覆盖而删除某只已持股票。

## 验证

172项测试通过，新增11项覆盖：

- 当前20只／4%唯一解；具有自由度的解析最小方差解及绑定行业上限。
- 无解、非PSD、非对称、候选数超限及不收敛处理。
- 投影约束与幂等性；实际净资产口径Beta、风险贡献求和及缺失风险处理。
- 严格／研究时间隔离、只读风险数组、版本和缓存文件篡改拒绝。
- 适配层的非唯一解Decimal转换、求解失败及实际持仓风险覆盖缺失时不发送目标。

完整回放还核对：逐日现金、实际股数、净值和次日成交；各目标／实际持仓的方差贡献求和；两账户净值逐日相同；重复完整运行结果与源代码指纹。

## 运行与输出

在项目根目录执行：

```bash
OPENBLAS_NUM_THREADS=1 python -m examples.run_risk_weights
OPENBLAS_NUM_THREADS=1 python -m unittest discover -s tests -q
```

支持 `--output`。默认目录 `outputs/risk_weights_20261109/`，包含：

- `comparison.json`、`net_values.csv`、配置及首次登记。
- 两组合子目录的订单、成交、公司行动、持仓、净值与调仓。
- `risk_audit.json`：实际／原目标／优化后风险、权重、求解状态及缺失原因。
- `selection_audit.json`：实际持仓、补位、资格退出及常规替换。
- `reproducibility.json`：重复运行及数值一致性验证。
