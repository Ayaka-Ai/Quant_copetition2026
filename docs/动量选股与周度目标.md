# 动量选股与周度目标生成

更新日期：2026 年 11 月 4 日。顺序 2 已实现：计算 20 日动量、检查股票资格、按行业及发行人约束选股，并在每周指定时点输出可交给组合账户的完整目标权重。规则参数仍为冻结的 V1.0.0。

## 运行与产出

在项目根目录运行：

```bash
python3 -m examples.run_momentum
python3 -m examples.run_momentum --check-local-b
python3 -m unittest discover -s tests -v
```

默认命令使用 40 只虚构股票、合成价格和成交额，验证固定规则及账户衔接，不依赖行情密钥。示例保留 503 代码冻结股票池的哈希验证，但使用单独标明的虚构股票池作测试。它不是实际美股回测。

默认输出到 `outputs/momentum_synthetic/`：

| 文件 | 内容 |
|---|---|
| weekly_targets.csv | 每个调仓日的入选股票、动量、成交额、行业、发行人、4% 目标权重及组合现金比例 |
| strategy_audit.json | 所有候选的资格、排名、入选与排除原因；预热、数据不足或错过截止等决定 |
| planned_targets.json | 完整目标权重、买入优先级和已有持仓数据保护列表 |
| orders.csv、trades.csv | 接入组合账户后的计划与模拟成交 |
| daily.csv、positions.csv | 每日净值及持仓账目 |
| rebalances.csv、targets.json | 账户实际接受或跳过的调仓计划 |
| summary.json | 费用参数、合成来源标记和账户计算摘要 |

本次示例包含 64 个行情交易日、5 个预热周和 7 个有效目标日；每次选 20 只、股票目标合计 80%，共形成 65 笔差额成交。日历另覆盖行情末尾之后的日期，因此不会把最后一个行情日星期三误当成一周结束。

`--check-local-b` 只读取已有 B 组缓存，输出 `outputs/momentum_b_readiness/data_readiness.json`。当前结果为 `data_not_ready`，列明常规时段、按时点复权、未复权股数口径、全市场美元成交额和实际发布时间等缺口，不生成任何目标事件。所有命令均不下载行情、不连接券商。

## 模块与输入

| 模块或类型 | 职责 |
|---|---|
| quant_signals.momentum.MomentumObservation | 单个证券某日的数据版本，包含实际可用时刻、复权及未复权收盘价、美元成交额、交易权限及公司行动状态 |
| quant_signals.momentum.momentum_snapshot | 按信号截止时间选取当时可得版本，计算 20 日动量及 30 日平均成交额 |
| quant_portfolio.MomentumCalendar | 独立于行情样本的完整交易日程与明确覆盖日期 |
| quant_portfolio.DataReadiness | 明确声明时段、复权、实际股数价格、成交额和发布时间五项验收结果，默认均为未验收 |
| quant_portfolio.load_momentum_config | 加载冻结配置，核验股票池哈希并拒绝不支持的规则设置 |
| quant_portfolio.build_momentum_targets | 返回周度 decisions 审计记录和可直接交给 simulate_portfolio 的 targets |

价格、成交额和权重使用 `Decimal`；未知字段用 `None`，真实零成交额用 `Decimal('0')`。`available_at` 必须带时区，表示该条记录全部字段已经可以使用的时刻，不能早于所属交易日收盘。若成交额晚于价格发布，可先保存成交额为 None 的早期版本，再保存完整版本。

每个证券、日期和可用时刻的组合只能有一条记录；同一天允许多个后续修订版本。每次信号只使用 `available_at <= cutoff` 的最新版本。后来的复权重算不能覆盖更早时点看到的历史；输入适配器还须保证同一截止时刻内的复权序列采用一致口径。

## 排名和资格检查

计算 `AdjClose(t) / AdjClose(t−20) − 1`，必须使用交易日历中对应的 21 个收盘价；缺少一天不前向填充，也不把较早记录挤进窗口冒充完整 20 日。资格检查另外要求最近 30 个交易日的全市场常规时段美元成交额均有效。

合格股票满足：当日未复权收盘价至少 5 美元、30 日平均成交额至少 2,000 万美元、行业及发行人已知、当时可交易且账户有权限、公司行动状态已核实。两个数值门槛均包含边界。缺少权限或可交易性信息属于数据不足，不自动推定为有权限。

合格股票按未四舍五入的动量降序，同分按代码 ASCII 升序。依次扫描，跳过已选发行人的另一股类和会突破行业 20% 的股票，选满 20 只后结束。每只仍为 4%；只选 17 只时为股票 68%、现金 32%。负动量不自动淘汰。

审计中的 `rank` 指资格过滤后的排名。因行业、发行人或持股数限制未入选的股票仍保留排名与原因；数据或经济资格不合格的股票保留对应原因，不与原始未过滤涨幅榜混淆。

## 周度时点与日历边界

日历覆盖起止日期必须由调用方明确提供，并包含覆盖期内全部交易日。只有周一至周日整个自然周落在完整覆盖范围内时，才确认该周最后一个交易日。星期五休市则采用星期四；星期五提前收市则仍采用星期五，并按实际收盘时间加 30 分钟形成截止时刻。

`as_of` 限制已到达的截止时刻；历史行情截止星期三并不意味着本周调仓日是星期三。交易日历可以包含未来已知日期，价格数据无需包含未来值。若当日收盘价的已知可用时刻晚于截止，则该周跳过，不因随后数据到齐而补信号。

`activation_date` 可指定开始生效的日期，首次建仓只发生在之后的首个合格周度时点。留空时从日历覆盖期开始做历史研究。函数负责离线历史目标生成，不创建在线定时任务，也不提交券商订单。

## 数据不足与清仓的区别

- 全局任一数据验收项未通过：返回 `data_not_ready` 决定，targets 为空，不向账户发送清仓目标。
- 全局历史不足 30 个交易日：返回 `warmup`，继续等待历史积累。
- 个别股票缺少历史、行业或其他字段：排除该候选，其他合格股票继续参加选择。
- 合格池为空且仍有数据缺口：不生成目标，保留已有仓位。
- 所有候选均可完整评价，但都因已知价格、成交额或不可交易条件不合格：生成明确的空权重目标，交由账户按下一交易日规则退出。

目标还带有 `unsafe_holding_symbols`。若其中某个证券已被账户持有，说明其当日实际价格或公司行动状态尚未核实，账户会将本次调仓记录为 `skipped_unsafe_holding_data`，整体暂停。未知候选本身不影响从未持有它的账户正常调仓。这一保护不会替代公司行动的现金与股数记账。
