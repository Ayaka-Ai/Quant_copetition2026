## 运行示例

在项目根目录运行：

```bash
python3 -m examples.run_portfolio
python3 -m examples.run_portfolio --sample-b
python3 -m unittest discover -s tests -v
```

第一条使用虚构股票 AAA、ZZZ 的固定价格，先分配 40% 加 40%，再调整为 ZZZ 80%，用于核对共同资金和调仓账目。它不是 V1 的选股配置。第二条读取现有 B 组缓存，以固定日期的 AAPL、MSFT 目标切换到 SPY 目标，仅用于 UTC 下一日柱收盘代理联调；不下载行情、不连接券商。

两个示例分别覆盖 `outputs/portfolio_synthetic/` 和 `outputs/portfolio_b/` 的派生结果，读取 V1 配置中的研究资金和费用参数，不改变原始缓存。无本地 B 组数据时仍可运行第一个示例和全部测试。旧双均线账户及 `examples.run_account` 保留原接口。

## 输入约定

接口为 `simulate_portfolio(sessions, bars, targets, config, *, corporate_actions=())`，从 `quant_backtest` 导入。金额、价格和权重均使用 `Decimal`，日期使用 `datetime.date`，时刻必须带时区。省略事件参数时保持原有无事件行为；事件参数目前采用公开研究版除息日现金与碎股开盘补偿代理，不代表严格 V1 的真实支付日模型。

| 输入 | 内容 |
|---|---|
| TradingSession | 交易日期、开盘时刻、收盘时刻、收盘价实际可用时刻，以及 regular 或 utc_calendar_day_proxy 标记 |
| SessionBar | 证券代码、交易日期、开盘价、收盘价、执行时点是否可交易；缺价以 None 表示 |
| TargetWeights | 信号所属交易日、信号可用时刻、完整目标权重映射、可选的买入优先顺序，以及需保护的已有持仓列表 |
| PortfolioConfig | 初始现金、每股佣金、最低佣金、单边滑点和成交模式 |
| CorporateAction | 来源事件 ID、代码、交易生效日、种类、可用时刻、精确拆股分子分母或实际每股现金、检查状态及依据 |

`sessions` 必须按时间顺序提供完整交易日程，包含没有个股行情的交易日。账户据此判断“下一交易日”，不把“下一根有记录的行情”当成下一交易日。交易所节假日和提前收市由调用方的日历适配器保证，账户不通过工作日猜测日历。

权重是净资产比例，`Decimal('0.04')` 表示 4%，所有权重非负且合计不超过 100%。一次目标是完整组合：本次省略的旧持仓目标为零，空映射表示计划清仓；某日没有目标事件表示继续持有，二者不同。

`buy_priority` 如提供，必须将全部正权重证券各列一次；留空时按代码排序。动量策略接入时应传动量排名顺序。此账户允许 SPY 80% 等基准目标，单股 4%、行业 20%、发行人去重和流动性筛选由选股与组合配置模块处理。

`unsafe_holding_symbols` 默认空，列出当日价格或公司行动状态未核实的证券。与已有持仓相交时，本次目标整体跳过并记录原因，不能把该证券从候选中排除后直接当作卖出信号。

以下是可以直接运行的两日合成示例，金额与价格均为演示输入：

```python
import datetime as dt
from decimal import Decimal as D
from quant_backtest import (
    PortfolioConfig, SessionBar, TargetWeights, TradingSession, simulate_portfolio,
)

utc = dt.timezone.utc
dates = [dt.date(2026, 11, 2), dt.date(2026, 11, 3)]
sessions = [
    TradingSession(day, dt.datetime.combine(day, dt.time(14, 30), utc),
                   dt.datetime.combine(day, dt.time(21), utc),
                   dt.datetime.combine(day, dt.time(21, 30), utc))
    for day in dates
]
prices = [SessionBar(symbol, day, price, price) for day in dates
          for symbol, price in [('AAA', D('100')), ('ZZZ', D('200'))]]
targets = [TargetWeights(dates[0], sessions[0].close_available_time,
                         {'AAA': D('0.04'), 'ZZZ': D('0.04')},
                         buy_priority=('ZZZ', 'AAA'))]
result = simulate_portfolio(sessions, prices, targets, PortfolioConfig())
print(result['summary'])
```

## 订单和时间顺序

信号必须晚于或等于本交易日收盘价可用时刻，且早于紧邻下一交易日的计划成交时刻。同一交易日最多一个完整组合目标。价格和日程重复、目标超过 100%、负权重、浮点金额等输入直接报错。

默认模式为 `next_session_open`，只接受 regular 日程。每只股票在信号时按下式确定股数：

```text
目标股数 = floor(目标权重 × 信号日组合净值 / 信号日收盘价)
订单股数 = 目标股数 − 当前股数
```

下一交易日先按代码升序执行卖单，再按买入优先顺序执行买单。买单只能因执行时可用现金不足而缩量，价格下降也不增加原订单股数；未成交余量取消。缺少开盘价或执行时不可交易的订单取消，不在之后的日期重试。没有下一交易日的期末订单保留为 `pending_end_of_sample`，期末持仓不自动清仓。

佣金按非零成交的 `max(最低佣金, 每股佣金 × 股数)` 计算。买卖滑点分别体现在成交价中，`slippage_cost` 只作归因。现金共用，研究中卖出净收入即时可用；现金、股数与成本不得为负。

`next_session_close_proxy` 是独立的工程模式，使用下一日程的 close。旧 UTC 缓存示例显式使用此模式和 utc_calendar_day_proxy 标记，不能传给默认开盘模式。该示例将柱终点作为最早可用边界，实际发布时间和可交易性未经验证，不能作为 V1 执行效果证据。

## 输出和缺失估值

返回 `orders`、`trades`、`daily`、`positions`、`rebalances`、`corporate_actions` 和 `summary`。示例输出对应的六张 CSV、目标记录和摘要 JSON，即使无订单或事件也保留 CSV 表头。

| 输出 | 用途 |
|---|---|
| orders.csv | 信号净值、目标权重、计划及成交股数、计划执行日、实际尝试时刻和最终状态 |
| trades.csv | 每笔实际模拟成交、参考价、成交价、佣金、滑点、现金变动与成交后持仓 |
| daily.csv | 每日现金、市值、净值、有效日收益、回撤、仓位和累计费用，可直接用于绘制净值曲线 |
| positions.csv | 持仓股数、估值价格日期、成本及已实现和未实现盈亏 |
| rebalances.csv | 每次完整目标、信号净值、是否因缺价跳过及原因 |
| corporate_actions.csv | 事件处理状态、分红资格、拆股前后数量、现金、碎股成本和已实现盈亏 |
| targets.json | 保留结构化权重的调仓记录 |
| summary.json | 参数、数据来源、末值、成交状态统计和使用边界 |

若持仓缺少当日收盘价，账户保留带日期的最近收盘估值，存入 `estimated_equity` 等估算字段；正式 `equity`、`net_value`、`daily_return` 和当日回撤为空。当天的目标调仓跳过。次日恢复估值后，也不将跨缺口变动误算为单日收益。摘要将 `performance_complete` 设为 false，完整期最大回撤不予计算；`observed_max_drawdown_pct` 仅描述有有效估值的观测点。

账户每天核对成交与公司行动现金流水、分配收入和盈亏恒等式。目标本身是否使用未来信息仍由上游策略负责，账户不能仅凭目标权重判断其研究过程是否合格。涉及已有持仓的未核实或未支持事件时，净值与收益设为空并取消普通调仓；明确的零持仓解除事件不能清掉已持有权益。

## 已完成验证与使用范围

项目当前 104 项测试通过。账户验证覆盖原有调仓和流水重建，以及除息日资格、拆股待执行目标、精确反向拆股、碎股与成本、事件去重、未知事件阻塞和零持仓解除。另有五组真实缓存固定目标账户逐日独立对账，共 2,505 个账户日。

合成例中价格固定，100,000 美元在四笔成交后为 99,860.045 美元；减少的 139.955 美元等于佣金 59.985 美元加滑点 79.97 美元，说明交易成本只扣一次。这是账户计算验收，不是策略收益结果。

税费、结算延迟、盘口成交量和市场冲击仍未建模；分拆、合并换股等复杂权益也尚未自动处理。旧合成例和 B 组例未传入事件，不会自动从日线猜测分红或拆股。正式 V1 仍需匹配的数据语义、真实可用时间和事件支付口径；公开版后续连接须保留其研究假设与未知项。
